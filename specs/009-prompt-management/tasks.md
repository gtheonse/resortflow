# Tasks: Prompt Management — Git-First Prompt Registry with Langfuse Mirror

**Input**: Design documents from `/specs/009-prompt-management/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/ (6 files), quickstart.md

**Tests**: Requested by the spec and the constitution ("TEST BEFORE ADVANCE"; the fail-closed matrix, lock/revocation invariants, `BASELINE_STALE`, per-tenant gate and the new dining metrics are mandatory test categories). Test tasks come **before** their implementation and MUST fail first.

**Organization**: Grouped by user story. **US1** (P1, MVP) dining prompt externalised with fail-closed variables; **US2** (P2) judge prompts pinned + `BASELINE_STALE` + per-tenant gate + dining metrics; **US3** (P3) sync, lock, promote, rollback, revocation, ownership. *Withdrawn by decision (2026-09-26): old US4 (Langfuse-link spike — ADR-052 D5 pre-decided as option ii) and old US5 (registry-to-Git `pull`, deferred).*

**US3 descoped by decision (2026-09-27), after the US2 checkpoint**: T063–T082b below (`prompts/sync.py`, `prompts/codeowners.py`, the lock/CODEOWNERS/verify CI steps, `prompt-sync.yml`/`prompt-drift.yml`, the runbook) were **not implemented**. Production runs `PROMPT_SOURCE=git` regardless, so US1+US2 are fully functional without US3; the constitution's "a deliberately degraded prompt MUST fail CI" rule is satisfied by US2 alone. Rationale and full disclosure: the Phase 7.6 handoff. Quickstart Scenarios 2, 4, 6, 7, 8 require `prompts.sync` and were not run — see `quickstart.md`.

**Phase mapping to plan.md's ordering table:** plan phase 1 -> tasks Phases 1-2 (setup and the single integration commit); plan 2 -> Phase 3 (US1); plan 3 -> Phase 4 (US2); plan 4 and 5 -> Phase 5 (US3, where the ownership tasks T067/T075 sit).

## Format: `[ID] [P?] [Story] [TIER] [CRIT?] Description`

- **[P]**: Can run in parallel with the previous task — different top-level area (`prompts/`, `eval/`, `agents/dining/`, `observability/`, `.github/` + `Makefile` + `docker-compose.yml`, `docs/` + `specs/`). Tasks inside one area (notably `prompts/`) are sequential.
- **[Story]**: US1 / US2 / US3. Setup, Foundational and Polish tasks carry no story label.
- **[TIER]**: Build-time model tier — `FRONTIER` / `MID` / `ECONOMY` (`docs/models.md`).
- **[CRIT]**: Falls in the never-economy table in `docs/models.md`; forces `FRONTIER`.
- All paths are relative to the repository root `resortflow/`.

## Model tier assignment *(mandatory — ResortFlow project override)*

Required by constitution Principle VI. **The rule** (`docs/models.md`): ECONOMY only where the spec fully determines the output; if it needs an unwritten judgment call it is not ECONOMY.

- **`[CRIT]` → `FRONTIER`** with a one-line justification (the CRIT area) at the end of the task. The CRIT areas that recur here: **allergen fidelity** (anything that decides whether a stated dietary restriction survives to the model call), **policy enforcement** (what the runtime may serve: lock, revocation, fail-closed variables, promotion), **tenant isolation** (the closed tenant model), **eval metrics and judge prompts** (including gate logic), and **all ADRs**.
- **ECONOMY** is used only where a contract in `specs/009-prompt-management/contracts/` or `data-model.md` fully specifies the output: constants, package skeletons, pins, env templates, CODEOWNERS/lock generation by command, prose runbooks, and test cases derived from an explicit criteria table.
- **MID**: orchestration wiring, CLI plumbing, adapters, CI workflows, non-trivial test design, and data files whose expected values need care.
- No phase is a declared whole-frontier phase; tiering was considered per task (see the summary at the end).
