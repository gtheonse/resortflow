# Phase 1 Data Model: Multi-Agent Orchestration

This feature does not introduce a new state container — `graph.state.ResortFlowState` and
`graph.models`'s entities (frozen since feature 001) already model almost everything
spec.md's Key Entities section needs. This document maps each spec-level entity onto the
existing frozen model, states the one additive schema amendment this feature makes
(ADR-023), and defines the new per-domain state shapes this feature adds by following the
`agents/dining/state.py` pattern.

## Spec entity → existing model mapping

| spec.md entity | Backed by | Notes |
|---|---|---|
| Itinerary | `graph.models.Plan` (+ `ResortFlowState.saga_id`) | A `Plan` is the itinerary's task decomposition; `saga_id` is the join key across every domain's ledger rows and saga events for that itinerary. |
| Domain Step | `graph.models.PlanTask` | One task per domain in the plan; `depends_on` expresses cross-domain ordering constraints (e.g. dinner before curtain); `constraints: dict[str, str]` carries the human-readable rule text. |
| Hold | `graph.models.Hold` | Already carries `idempotency_key` (merge key), vendor `hold_id` (nullable until vendor responds), `status: HoldStatus`, `expires_at`. No change needed. `Release` (reached via `HumanApproval --> Release: declined`, which also covers explicit guest cancellation per ADR-026) calls each domain's `release_*`/`release_hold` tool for every hold still `pending`/`held` on the itinerary and writes a `released` `SagaEvent` — this is what satisfies spec.md's FR-022. |
| Conflict | *(new, this feature)* — see below | Not previously modeled; output of the deterministic conflict checker. |
| Recovery Alternative | `graph.models.Proposal` (new instances, generated by Recovery) | A recovery alternative is structurally just another `Proposal` — no new type needed, only a new *producer* of proposals (the Recovery Agent). |
| Replan Attempt | `ResortFlowState.replan_count: int`, bounded by `MAX_REPLAN_COUNT = 3` | Already exists; this feature adds the first caller that increments and checks it. |
| Escalation | `ResortFlowState.escalate: bool` + new `escalate_reason: str | None` (ADR-023) | `escalate_reason` is additive; see amendment below. |

## New type: `Conflict`

Not previously modeled anywhere in `graph.models`. The deterministic conflict checker
(`CONFLICT_CHECK` node, no LLM) produces zero or more of these per fan-out pass, from the
`starts_at`/`ends_at`/`location_zone`/`party_size` fields already present on every
`Proposal`. Travel-time resolution between two `location_zone` values uses a static
per-tenant matrix, not a live service — see ADR-025.

```python
class Conflict(ResortFlowModel):
    """A detected incompatibility between two or more proposals in the same
    plan. Produced only by the deterministic conflict checker — never by an
    LLM (Constitution: DETERMINISM FIRST)."""

    conflict_id: str
    kind: str
    """`schedule_overlap` | `travel_infeasible` | `party_size_mismatch`."""
    proposal_ids: list[str]
    """The two (or more) proposals in conflict."""
    detail: str
    """Human-readable, e.g. "18:30 dinner ends 19:15; 400m/6min travel leaves
    only 4 minutes before 19:19 curtain — insufficient."."""
```

`Conflict` instances are transient (computed each conflict-check pass, not persisted as
their own `ResortFlowState` channel) — they drive the `ConflictCheck --> Planner: replan needed`
edge and are recorded into `saga_log` as a `SagaEvent` (`kind="conflict_detected"`) for
audit, rather than carried as a first-class state list. This avoids a fourth reducer for a
value that is fully reconstructible from `proposals` at any point.

## `ResortFlowState` amendment (ADR-023)

Three additive keys, all with safe defaults, appended to the existing twenty-key
`TypedDict`:

```python
graph_version: str
"""Set once at thread start from a small build-time constant; compared on
resume per ResortFlow-HITL-Durability-State.md §8 mitigation #1."""

clarification_count: int
"""Default 0. Incremented by CLARIFY (ADR-024) each time it asks a
follow-up question. Bounded by MAX_CLARIFICATION_COUNT."""

escalate_reason: str | None
"""Default None. One of {"replan_bound", "clarification_bound",
"compensation_failed"}, set exactly once, at the point escalation fires."""
```

New constant, co-located with `MAX_REPLAN_COUNT` in `graph/state.py`:

```python
MAX_CLARIFICATION_COUNT: Final[int] = 2
"""Hard bound on the IntentRouter <-> Clarify cycle (ADR-024). Breach sets
escalate=True, escalate_reason="clarification_bound", and routes to
HUMAN_HANDOFF."""
```

No existing key changes shape or meaning. This is a pure append, satisfying
`ResortFlow-HITL-Durability-State.md` §8 mitigation #4 ("additive state changes only").

## New per-domain state shapes

Following the `agents/dining/state.py` precedent exactly (`DiningState(ResortFlowState)` as a
`TypedDict` superset with `NotRequired` scratch fields), each new domain gets its own
state module:

```python
# agents/entertainment/state.py
class EntertainmentState(ResortFlowState):
    intent: NotRequired[EntertainmentIntentParsed | None]
    selected_section_id: NotRequired[str | None]
    hold_attempt: NotRequired[int]
    approval_rejected: NotRequired[bool]

# agents/stay/state.py
class StayState(ResortFlowState):
    intent: NotRequired[StayIntentParsed | None]
    selected_offer_id: NotRequired[str | None]
    hold_attempt: NotRequired[int]
    approval_rejected: NotRequired[bool]

# agents/wellness/state.py
class WellnessState(ResortFlowState):
    intent: NotRequired[WellnessIntentParsed | None]
    selected_proposal_id: NotRequired[str | None]
    hold_attempt: NotRequired[int]
    approval_rejected: NotRequired[bool]

# agents/gaming/state.py
class GamingState(ResortFlowState):
    """No hold/approval fields — gaming is read-only (Constitution Principle
    II: enforced by the absence of mutating tools, not by state shape alone,
    but the state shape reflects it too: there is no hold_attempt because
    there is no hold)."""
    intent: NotRequired[GamingIntentParsed | None]
```

Each domain's `*IntentParsed` TypedDict follows `agents/dining/state.py`'s
`IntentParsed` shape (`ambiguous_fields: list[str]` is the field `CLARIFY`, ADR-024,
reads to decide whether a follow-up question is needed at all — this is the mechanism
FR-020 attaches to, not a new field).

## Supervisor-level state (new, this feature)

No new `ResortFlowState` key is needed for the supervisor's own bookkeeping beyond `plan` and
`replan_count`, both already frozen. The supervisor's fan-out/fan-in over the five domain
subgraphs is expressed at the graph-topology level (parallel edges into `FanOut`'s five
domain nodes, per `docs/ResortFlow-Enterprise-Multi-Agent-Plan.md` §4's `stateDiagram-v2`), not
as additional state shape — each domain subgraph writes its own `proposals`/`holds`
contributions through the existing `merge_proposals`/`merge_holds` reducers, which are
exactly what makes concurrent multi-domain writes safe in the first place (their
same-superstep, no-lost-writes property, `graph/state.py`'s own reducer contract).

## `SagaEvent.kind` vocabulary (extended, non-breaking)

`SagaEvent.kind` is a free `str` field (`graph.models.SagaEvent`), so extending its
vocabulary is not a schema change. This feature adds the following values, used by the
new nodes:

- `clarification_requested` / `clarification_resolved` — written by `CLARIFY`.
- `conflict_detected` — written by `CONFLICT_CHECK`, carrying the `Conflict.conflict_id`
  and `kind` in `detail` (bounded scalars only, per the field's existing contract).
- `partial_itinerary_proposed` — written by `PLANNER` when a domain has zero availability
  (spec.md's clarified FR-021) and the plan proceeds without it.
- `escalated` — written wherever `escalate=True` is set, carrying `escalate_reason` in
  `detail`.

Per ADR-027, the dead-letter path Constitution Principle III requires for a failed
compensation is this same Postgres-mirrored `saga_log`, filtered by
`escalate_reason="compensation_failed"` — not a new dedicated table.

## Node registry amendment (additive)

Two new frozen node names are added to `graph/nodes.py`'s `ALL_NODES` (additive, per
ADR-024; `OFFER_AGENT` and `HUMAN_HANDOFF` are unchanged existing reservations, resolved
by ADR-020, not renamed):

```python
CLARIFY: Final[str] = "clarify"
```

`HUMAN_HANDOFF` transitions from "reserved, unmounted" to "reserved, mounted" — the
constant's value is unchanged; only whether it is compiled into the `StateGraph` changes,
which is not a persistence-format break (a node that now exists cannot collide with a
node name that already existed unused).
